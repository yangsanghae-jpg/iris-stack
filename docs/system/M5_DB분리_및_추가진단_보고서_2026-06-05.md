## Part 2. 추가 진단 5가지

### 2.1 Grafana 대시보드 (L5 활용 가능?)

**포트:** Grafana = **`http://127.0.0.1:3030`** (호스트 매핑 `3030→3000`)  
`3001`은 diagnosis-tool UI (Python http.server) — Grafana 아님.

**프로비저닝된 대시보드 (4개):**

| 파일 | 용도 추정 |
|------|-----------|
| `iris-infra.json` | 인프라 메트릭 |
| `iris-product-readiness.json` | 제품 준비 상태 |
| `iris-services-status.json` | 서비스 Up/Down |
| `iris-v25-k5.json` | **K5 telemetry** (정상호출 ≥95%, Caller 누락률, Fallback 알람) |

**데이터소스 (3030/api/datasources):**

| 이름 | 타입 | URL |
|------|------|-----|
| Prometheus | prometheus (default) | `http://prometheus:9090` |
| Loki | loki | `http://loki:3100` |

**판정:** V2.5.1 §11 "통제 화면"을 **Streamlit 신규 작성 없이 Grafana 패널 확장**으로 단축 가능. `iris-v25-k5.json`이 이미 V2.5 KPI 골격을 담고 있음.

### 2.2 Loki 적재 현황 (L5 telemetry 가능?)

```bash
curl http://127.0.0.1:3100/loki/api/v1/labels
# → {"status": "success"}  (라벨 목록 비어 있음)

query_range {job=~".+"} → streams: 0
```

**판정:** Loki 인프라는 살아 있으나 **K5가 미기동**이라 `iris_k5_telemetry` 로그가 아직 없음. K5 router 기동 + telemetry write만 되면 Grafana `iris-v25-k5` 패널이 바로 살아남.

### 2.3 Promtail 스크랩 경로

**실제 마운트된 설정** (`observability/promtail/promtail.yml`):

```yaml
scrape_configs:
  - job_name: iris-k5-telemetry
    static_configs:
      - labels:
          job: iris_k5_telemetry
          source: K5
          __path__: /mnt/iris-system-storage/iris_k5_telemetry*.log
```

**Docker volume:**

```yaml
# docker-compose.observability.yml
- /Users/iris/Documents/0Dev/iris-system/storage:/mnt/iris-system-storage:ro
```

**호스트 `iris-system/storage/` 현황:**

```text
storage/
├── _index.db (0 bytes — placeholder)
└── sqlite/
```

→ `iris_k5_telemetry*.log` **아직 없음**. Promtail 파이프라인(V2.5 §8.1 regex)은 이미 작성됨.

**판정:** Phase 5.5/5.6 telemetry → Loki → Grafana 경로는 **코드만 연결하면 됨**. 인프라 신규 구축 불필요.
